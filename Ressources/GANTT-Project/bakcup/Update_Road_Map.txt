### 1. L'Ingénieur Infrastructure & eBPF (L'Ops) - Antoine

C'est celui qui maîtrise le terrain de jeu (Kubernetes/Docker) et l'outil de collecte.

- **Mission principale :** Mettre en place l'environnement et configurer Tetragon pour qu'il ne soit ni muet, ni trop bavard.
- **Tâches :**
    - Déployer un cluster Kubernetes local (Kind ou Minikube).
    - Installer Tetragon en tant que DaemonSet.
    - Écrire les **TracingPolicies** (fichiers YAML) pour filtrer les événements (ex: on veut voir les `execve` et les `tcp_connect`, mais pas forcément tous les `read` sur des fichiers logs).
- **Livrable :** Un flux JSON propre et filtré, accessible par le service Python.

### 2. L'Architecte de Données (Le "Mapper" Python) : Ahmed

C'est celui qui traduit le langage "Système" en langage "Graphe".

- **Mission principale :** Transformer les logs plats de Tetragon en une structure relationnelle.
- **Tâches :**
    - Créer le script d'ingestion qui lit le JSON en temps réel.
    - Modéliser les données avec une librairie comme **NetworkX** (en mémoire) ou une DB comme **Neo4j**.
    - Définir les nœuds (ex: `Pod`, `Processus`, `Fichier`, `IP Externe`) et les arêtes (ex: `SPAWNS`, `MODIFIES`, `CONNECTS_TO`).
- **Livrable :** Une classe Python capable de dire : "Voici l'état actuel du système sous forme de graphe".

### 3. Le Développeur Algorithmique (L'Analyste)

C'est le rôle "Cerveau". Il prend le graphe et cherche les problèmes.

- **Mission principale :** Comparer le graphe en temps réel avec un "modèle de référence" (baseline) pour détecter les anomalies.
- **Tâches :**
    - Enregistrer une phase d'apprentissage (comportement normal du conteneur).
    - Développer l'algorithme de détection : "Si le nœud `nginx` crée une arête vers le nœud `/etc/passwd`, ALERTE".
    - Gérer la persistance des profils de comportement (sauvegarder le graphe "sain" en JSON ou Pickle).
- **Livrable :** Le moteur de détection qui lève une exception ou une alerte quand le graphe change anormalement.

### 4. Le Red Teamer & Visualiseur (Le QA / Frontend) (Jeremy)

C'est celui qui attaque le système pour prouver qu'il fonctionne, et qui rend les résultats visibles.

- **Mission principale :** Simuler des attaques et fournir une interface pour voir le graphe.
- **Tâches :**
    - Développer des scripts d'attaque (ex: *Reverse Shell*, *Privilege Escalation*) à lancer dans les conteneurs surveillés.
    - Créer une petite visualisation web (avec **Streamlit** ou **Dash** en Python) pour afficher le graphe généré par le collègue n°2.
    - Vérifier que les attaques du script apparaissent bien en rouge sur le graphe.
- **Livrable :** Une suite de tests d'intrusion et un Dashboard de visualisation.
